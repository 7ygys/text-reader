# 屏幕区域实时文字朗读工具

Windows 后台驻留工具：框选屏幕指定区域，自动识别区域内滚动更新的文字，并对**新增文本**排队式语音朗读。核心适配单机游戏聊天/对话框（如 RimWorld 的 RimChat 模组、游戏内聊天框）。默认朗读所有识别到的新文本，也可切换到"仅朗读带 `【朗读】` 标签"模式。

全程无生成式 AI 大模型参与：截图（windows-capture/dxcam/mss）→ 帧差过滤（pHash）→ 离线 OCR（RapidOCR/ONNX）→ 文本清洗增量检测 → 队列排队 → TTS 朗读（edge-tts / pyttsx3）。

---

## 一、技术可行性评估（相对原始方案的调整）

原方案整体可行，以下是评估后所做的必要调整，均为"可用性/稳健性"层面的修正，模块结构与业务链路保持不变：

| 调整点 | 原因 |
| :--- | :--- |
| 截图后端改为 **windows-capture 主 + dxcam/mss 后备** | windows-capture 基于 DXGI/WGC，对全屏/独占游戏的兼容性与性能优于纯 dxcam；失败时自动降级 |
| OCR 兼容 1.x / 2.x 两种返回格式 | `rapidocr_onnxruntime` 新旧版本返回值结构不同，做防御式解析避免升级即崩 |
| 增量检测改为**累积式完整句检测** + 启动预热 | 滚动/打字中间帧常把一句话切成碎片（如"我今天要上早八"被识别成"我/今天要上/早八"），旧的行签名去重会把中间碎片误判为已读而漏读。现在把跨帧碎片按顺序累积拼成完整句，遇到句末标点或新内容打断时一次性输出，避免漏字 |
| 默认朗读**所有识别到的新文本**（`read_all`），可切换为仅朗读带**【朗读】标签**并合并短句 | 默认适配游戏聊天/字幕（如 RimChat）；`read_all=false` 时只朗读带标签行，避免误读 UI/系统提示；连续短句自动合并，朗读更连贯 |
| edge-tts 增加 **20s 超时**、**3 次自动重试** 与失败回退 | 断网/限流时合成可能失败（如 No audio was received），先重试再降级到 pyttsx3，不中断朗读；pyttsx3 改用显式事件循环，避免重复调用只读几个字就中断 |
| **NoAudioReceived 快速失败不重试** + 文本清洗 | edge-tts 对"空文本/仅标点/含控制符"会直接返回 `No audio was received`；先清洗剔除这些文本，对服务端确定性拒绝不再无谓重试，立即走离线兜底，避免 3 次重试拖慢朗读 |
| **连续失败 10s 冷却**（edge-tts） | 连续失败 3 次后进入短暂冷却走 pyttsx3，冷却结束自动恢复尝试网络合成，成功即重置；避免反复请求网络造成长时间卡顿 |
| **预取下一句**（reader 朗读当前句时提前合成队列下一句并缓存） | edge-tts 每次合成有 1~2s 网络延迟，逐句串行会明显卡顿；预取后连续朗读几乎无缝 |
| 累积检测支持 **OCR 中间漏字补全** | OCR 某帧漏识别中间几个字、下一帧补全时，用子序列匹配判断 line 是 acc 的更完整版本并替换，避免整句中间缺字 |
| **标点分段输出**（以断点标点作为新文本的分隔符） | 遇到括号 `()（）【】[]{}`、逗号 `,，、`、句号 `。.`、感叹号 `！!`、问号、分号、冒号等断点标点时，暂停采集，把"上一个断点之后到此处（含标点）"的文本作为一个【新文本】输出，保证文本完整、停顿点自然 |
| **空闲冲刷残留句**（Reader 空闲约 1.5s 强制输出累积残留） | 暂停游戏时画面静止、无新帧触发累积 flush，最后一句（常无句末标点）会一直读不出来；Reader 检测到队列空闲超时后强制输出残留，避免最后一句漏读 |
| **标点断句**（以句末标点作为停顿边界 + 行首标点标记新句） | 累积的尾部续接不再用 1 字符的模糊重叠拼接，最小重叠提高到 2 且 line 以标点开头时视为新句不续接，避免把两条独立消息错误拼成一句、停顿点更自然 |
| **碎片拼全不丢字**（宽松过滤 + 短无标点块累积拼接） | OCR 把一句话拆成多块（如"我今天要上早八"被识别成"我/今天要上/早八"）时，采集阶段不再因 min_length=2 过滤掉单字碎片；短且无标点的相邻块会累积拼接成完整句后再输出，解决"中间字被忽略、漏字"问题 |
| **采集密度优化**（提高 fps、降低 phash 阈值、周期强制 OCR） | 默认 fps 从 0.5 提到 3、phash_threshold 从 30 降到 10，并新增 force_ocr_interval 强制 OCR 兜底，避免聊天消息出现时因画面变化不足或采样太稀而漏采 |
| **批量朗读·无间隔连贯**（攒批合并 + 流水线预取） | 先堆积一批新文本（攒满 batch_size 条或超时 batch_timeout）合并成一句朗读，edge-tts 按标点自然停顿、批内无逐句合成/切换卡顿；朗读当前批时后台预取下一批并提前合成（preload_and_wait），批与批之间无缝衔接，读出期间持续采集的新文本不会拖慢朗读。可调 batch_size / batch_timeout / batch_max_chars |
| 音频播放失败**只记日志不崩溃** | 游戏独占音频设备时 MCI 播放可能失败，应保证程序继续运行 |
| 界面改用 **PySide6(Qt6)** | PyQt5(Qt5.15) 在 Python 3.14 下创建 QApplication 会原生崩溃(0xC0000409)，Qt6 无此问题；API 与 PyQt5 兼容 |
| 每次启动**强制重新框选**，区域不跨会话保存 | 符合"每次使用都重新框选"的交互习惯；一次运行中可多次框选更新 |
| 区域边框**始终显示**并带半透明填充 | 随时能看到监听范围，停止监听也不消失 |
| 多显示器只采集所选输出（默认主屏） | 默认按主屏坐标裁剪；跨屏采集需要额外配置 |

### 未达成的硬指标（如实说明）
- **部分独占全屏游戏**：windows-capture 已大幅提升兼容性，但仍有少数使用特殊独占模式的 DX9/11/12/Vulkan 游戏可能无法被任何常规 API 捕获；若遇到黑屏，请把游戏改为"无边框窗口"或"窗口化"模式。
- **常规游戏字体识别 ≥95%**：RapidOCR 对清晰常规字体可达，但小字号/艺术字体/暗背景会下降，可通过调大框选区域、调高采集频率缓解。

## 二、安装

**所有下载内容（Python 依赖、pip 缓存、OCR 模型）一律放在工作区 `e:\阅读器` 内，不写入系统。** 支持 Python 3.8+（含 3.14）。

```bat
# 一键安装：自动建 .venv，依赖全部装进工作区，pip 缓存放 .pip-cache
install.bat
```

或手动安装：

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

### 下载内容位置

| 内容 | 位置 | 说明 |
| :--- | :--- | :--- |
| Python 依赖 | `.venv\` | 虚拟环境，隔离于系统 |
| pip 缓存 | `.pip-cache\`（install.bat） | 避免写入用户 `%LOCALAPPDATA%` |
| OCR 模型 | `models\` | RapidOCR 首次运行自动下载，通过 `MODELSCOPE_CACHE`/`HF_HOME` 重定向到此处 |
| 运行日志 | `screen_reader.log` | 工作区内 |

> 说明：首次运行开始监听时，OCR 会自动下载模型到 `models\`（约几十 MB，仅一次），之后完全离线。

## 三、使用方法

```bat
run.bat            # 前台运行（控制台看日志）
start.bat          # 后台静默运行（无窗口，通过托盘或任务管理器关闭）
```

| 快捷键 | 功能 |
| :--- | :--- |
| `Ctrl+Alt+S` | 重新框选监听区域；一次运行中可多次框选更新（ESC 取消） |
| `Ctrl+Alt+R` | 开始 / 停止监听；停止时会清空待朗读队列 |
| `Ctrl+Alt+A` | 微调监听区域（数字微调） |
| `Ctrl+Alt+T` | 朗读测试 |

托盘图标菜单：开始/停止监听、重新框选、区域微调、朗读测试、设置、退出。

### 首次使用流程
1. 运行程序 → 托盘出现图标（`run.bat` 会额外显示控制台日志窗口）。
2. 程序**每次启动都会清空上次区域**，必须先用 `Ctrl+Alt+S` 拖拽框选游戏聊天区域。
3. 框选后会出现**半透红色边框**，并始终显示；可重复按 `Ctrl+Alt+S` 更新区域。
4. `Ctrl+Alt+R` 开始监听（首次会预热，不朗读已有旧文本）。
5. 监听区域内出现**新增文本**（默认朗读所有有效行）→ 自动排队朗读；停止监听会清空待朗读队列。

> **RimWorld RimChat 快速上手**：框选 RimChat 聊天框区域即可。程序默认朗读所有新聊天行。若想让每句清晰分开、减少误读，可在设置里开启"仅朗读带 `【朗读】` 标签的文本"，或直接在聊天内容前加该前缀。

### 窗口跟随（可选）
在 `config.json` 中设置 `"window_title": "游戏窗口标题关键字"`，监听区域会随该窗口移动而平移。

## 四、配置说明（config.json，运行时自动生成）

```jsonc
{
  "region": [0, 0, 0, 0],            // 监听区域 x,y,w,h（本次运行有效，不保存）
  "window_title": "",                // 窗口跟随关键字，留空关闭
  "fps": 1.0,                        // 采集频率，越大越实时、占用越高
  "show_border": true,               // 是否显示区域边框（边框始终显示，不受监听状态影响）
  "border_color": [255, 40, 40],     // 边框颜色
  "border_alpha": 35,                // 边框填充透明度 0-255，35 为隐约可见
  "capture_backend": "auto",         // 截图后端：auto/wcap/dxcam/mss
  "output_idx": 0,                   // 多显示器时采集哪个屏幕
  "hotkeys": { ... },                // 快捷键（keyboard 库格式）
  "tts": {                           // 语音合成
    "engine": "edge-tts",            // edge-tts(网络,推荐) / pyttsx3(离线)
    "voice": "zh-CN-XiaoyiNeural",   // 晓伊-可爱少女音；设置对话框可换
    "rate": "+0%", "volume": "+0%"
  },
  "reader": {                        // 朗读调度
    "queue_size": 30,                // 队列长度，满则丢弃最旧
    "min_length": 2,                 // 忽略过短文本
    "history_size": 300,             // 去重历史
    "dedupe_consecutive": true,      // 连续重复只读一次
    "read_all": true,                // 朗读所有识别到的有效文本（游戏聊天/字幕）
    "read_tag": "【朗读】",            // read_all=false 时，只朗读以此标签开头的文本（空字符串表示不过滤）
    "merge_short_max_chars": 12      // 小于该长度的连续短句会合并，使朗读更连贯
  },
  "filters": {                       // 文本清洗
    "drop_punct_only": true,         // 纯标点
    "drop_digits_only": true,        // 纯数字
    "drop_bracket_only": true,       // 纯 [UI按钮]
    "drop_patterns": []              // 自定义正则，如 ["^\\[System\\]"]
  },
  "phash_threshold": 30,             // 帧差灵敏度(0~256)，越小越敏感
  "warmup_on_start": true,           // 启动预热，不朗读旧文本
  "auto_start": false                // 开机启动时自动监听
}
```

## 五、注意事项与限制

1. **全屏游戏**：截图默认使用 `windows-capture`，对大多数"全屏"和独占游戏有效；若仍黑屏，请在 `config.json` 中把 `capture_backend` 改为 `"dxcam"` 或 `"mss"`，或把游戏设为"无边框窗口/窗口化"模式。
2. **edge-tts 需要联网**；断网自动降级 pyttsx3（音质较机械，离线可用）。音频播放：主程序用 **pygame(SDL)** 在 Qt 主线程播放（经信号桥接，规避 pygame 在后台线程崩溃、以及 MCI 对 mp3 静默无声的问题），MCI 仅作后备。
3. **多显示器**：默认只采集主屏；其他屏幕改 `output_idx`，或依赖 mss 后备（mss 支持虚拟桌面）。
4. **朗读范围**：默认朗读所有识别到的新文本（`reader.read_all=true`）；若只想要特定内容，可在设置或 `config.json` 中把 `read_all` 设为 `false`，并设置 `reader.read_tag`（如 `【朗读】`），此时只朗读带该前缀的行。
5. **声音异常排查**：若某个程序（如某些独占音频的游戏）在前台时本程序无声，请先看 `screen_reader.log` 是否出现"pygame 音频初始化失败"或"播放失败"；通常切到窗口化/无边框模式即可恢复。若其他软件（如播放器）在前台时正常，则说明音频链路正常，需检查 OCR 是否识别到文本。若日志出现 `edge-tts 合成失败: No audio was received`，多为**网络波动/微软服务偶发限流**，程序已自动重试 3 次再降级到 pyttsx3。
6. **选框在全屏独占游戏中不显示**：红色选框是普通置顶窗口，无法覆盖**独占全屏**模式的游戏画面（操作系统层限制，非本程序缺陷）。若想看到选框，把 RimWorld 等游戏设为**"窗口化"或"无边框窗口"**即可。注意：**选框不可见不影响监听**——截图直接抓取屏幕，只要区域坐标正确，即使选框被游戏盖住，朗读照常工作。
6. **低占用**：默认 1 帧/秒采集 + 帧差过滤，稳态 CPU 远低于 5%；调高 fps 会线性增加占用。
7. **日志**：运行日志写入 `screen_reader.log`，排查问题优先看这里。
8. 若全局热键不生效，尝试**以管理员身份运行**（部分环境 keyboard 库需要更高权限）。

## 六、目录结构

```
├── main.py                 # 主程序入口 + 核心控制器
├── modules/
│   ├── region_selector.py  # 区域交互：框选、状态边框、微调、设置
│   ├── capture.py          # 截图采集：windows-capture + dxcam + mss 后备、窗口跟随
│   ├── frame_filter.py     # 帧差过滤：pHash 感知哈希
│   ├── ocr_engine.py       # OCR：RapidOCR(ONNX) 离线识别
│   ├── text_processor.py   # 文本清洗 + 增量检测
│   ├── speech.py           # TTS：edge-tts / pyttsx3 + 音频播放调度
│   ├── qplayer.py          # 主线程 pygame 音频播放桥（Qt 信号桥接，规避崩溃）
│   ├── reader.py           # 朗读调度：队列 + 串行消费线程
│   ├── tray_control.py     # 系统托盘
│   ├── hotkeys.py          # 全局快捷键
│   └── config_manager.py   # 配置持久化
├── requirements.txt
├── run.bat / start.bat     # 启动脚本
└── config.json             # 运行时自动生成
```
